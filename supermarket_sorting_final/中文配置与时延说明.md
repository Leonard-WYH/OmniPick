# supermarket_sorting_final 中文配置与时延说明

本文对应当前 `supermarket_sorting_final`。数值来自现有 Python、Shell、YAML 和行为树
配置，用于定位机器人为什么等待、为什么超时以及控制和规划多久更新一次。

## 1. 时间参数分类

| 类型 | 常见命名 | 是否固定等待 | 含义 |
| --- | --- | ---: | --- |
| 停稳/保持 | `SETTLE`、`DWELL`、BT `Wait` | 是 | 反馈到位后继续保持，时间到才进入下一状态 |
| 故障上限 | `TIMEOUT`、`allowance` | 否 | 条件提前满足就立即继续，只有长期不满足才触发保护 |
| 周期/频率 | `frequency`、`rate`、timer | 否 | 决定控制、规划、地图或状态更新速度 |
| 时间容差/预测窗 | `transform_tolerance`、`model_dt` | 否 | 用于同步、TF或轨迹预测，不会主动停车 |

排查“到位后仍然顿一下”先看 `SETTLE/DWELL`；排查“卡很久后才失败”看
`TIMEOUT`；动作本身慢则应检查速度、加速度和 `joint_slew`。

## 2. 文件职责

### 启动与导航

- `../run_final_test.sh`：宿主机总入口，负责随机任务、容器、RViz 和日志；
- `scripts/run_nav2_mission.sh`：Client 内启动 SLAM、Nav2、感知和任务节点；
- `scripts/check_nav2_ready.sh`：检查节点、Action、话题和 TF 是否就绪；
- `launch/navigation_stack.launch.py`：编排 odom adapter、SLAM 和 Nav2；
- `config/nav2_params.yaml`：NavFn、DWB、代价地图、BT Navigator 和行为服务器；
- `config/nav2_mppi_controller.yaml`：MPPI 局部控制器参数；
- `config/slam_toolbox_params.yaml`：在线建图和 TF 参数；
- `config/navigate_to_pose_w_replanning_and_recovery.xml`：普通/空载导航行为树；
- `config/navigate_to_pose_tissue_safe.xml`：双臂夹持负载导航行为树。

### 任务、抓取和放置

- `src/supermarket_sorting_nav2/sorting_config.py`：正式任务的速度、阈值、时延和
  商品专用配置；
- `src/supermarket_sorting_nav2/sorting_state_machine.py`：抓取、运输和放置状态切换；
- `src/supermarket_sorting_nav2/motion_control.py`：Nav2 接管、直接底盘控制和机械臂
  并行动作；
- `src/supermarket_sorting_nav2/visual_servo.py`：两阶段视觉伺服；
- `src/supermarket_sorting_nav2/product_scheduler.py`：货柜选择和放置点分配；
- `src/supermarket_sorting_nav2/inventory_tracking.py`：订单、库存记忆和已抓实体剔除；
- `src/supermarket_sorting_nav2/tissue_handling.py`：双臂夹持动作；
- `src/supermarket_sorting_nav2/nav2_manipulation_client.py`：通用 Nav2/放置基础常量；
- `src/supermarket_sorting_nav2/baseline_grasp_controller.py`：早期基线与50 Hz控制循环；
- `tests/test_orange_placement.py`：橙子放置回归测试；
- `tests/test_tissue_table_release.py`：双臂落桌、释放、抬起和退出回归测试。

## 3. 启动阶段的等待

| 位置 | 当前值 | 类型 | 作用 |
| --- | ---: | --- | --- |
| `run_final_test.sh` 的 `wait_for_container` | 每1 s轮询 | 周期 | 检查容器是否进入 Running |
| 等 Server 容器 | 最多60 s | 超时 | 容器启动即继续 |
| Server Running 后 | 6 s | 固定等待 | 给仿真模型、传感器和 ROS 发布器初始化 |
| 抓取 `/supermarket_sorting/task` | 最多30 s | 超时 | 记录任务消息，超时只告警 |
| RViz 等 Client | 最多120 s | 超时 | Client 启动即打开 RViz |
| `NAV2_READY_TIMEOUT` | 默认45 s | 总超时 | Nav2 就绪检查上限 |
| 就绪检查失败重试 | 每1 s | 周期 | 重新检查节点、Action、话题和 TF |
| 关键话题单次读取 | 3 s | 超时 | 等 `/odom`、`/nav2/odom`、`/scan` |
| `/map` 单次读取 | 7 s | 超时 | 首张在线地图通常更慢 |
| 每段 `tf2_echo` | 3 s | 超时 | 验证三段 TF 链 |

`scripts/run_nav2_mission.sh` 的长驻进程等待不是动作延时；Client entrypoint 也没有
人为 `sleep`。

## 5. 单臂商品放置时延

通用放置常量定义在 `nav2_manipulation_client.py`，正式随机状态机直接复用；商品
覆盖和连续动作参数位于 `sorting_config.py`。

| 常量 | 当前值 | 加在哪里 |
| --- | ---: | --- |
| `PLACE_ACTION_SETTLE_SEC` | 0.10 s | 通用伸手/撤手动作到位后 |
| `PLACE_ADVANCE_TO_LOWER_SETTLE_SEC` | 0.00 s | 前伸到位立即进入下放，不额外停顿 |
| `PLACE_LOWER_SETTLE_SEC` | 0.10 s | 普通商品下降到位后再松开 |
| `CHENGZI_PLACE_LOWER_SETTLE_SEC` | 0.00 s | 橙子通过独立高度/速度门槛后立即松开 |
| `PLACE_RELEASE_SETTLE_SEC` | 0.30 s | 普通商品爪子完全打开后等待落稳 |
| `BROAD_RELEASE_SETTLE_SEC` | 0.30 s | 三明治、合味道等宽包装打开后等待落稳 |
| `POST_RELEASE_CLEARANCE_SETTLE_SEC` | 0.00 s | 身体抬高到位后不增加固定等待 |
| `PLACE_LIFT_SETTLE_SEC` | 0.10 s | 通用包装器的抬起到位保持 |
| `RIGHT_ARM_RETURN_SETTLE_SEC` | 0.25 s | 右臂回到运输/初始姿态后 |

橙子不会因为“延时到了”就松爪。进入松爪前还要同时满足测得的末端高度、升降速度、
命令误差、机械臂到位和反馈新鲜度；`CHENGZI_PLACE_LOWER_TIMEOUT_SEC=30 s` 只会在
长期不满足时保护失败，不会强制开爪。

放置动作速度也会改变总时长，但不是固定等待：

| 动作 | 通用值 | 橙子 | 苹果 |
| --- | ---: | ---: | ---: |
| 展开放置姿态 | 1.25 | 0.60 | 1.00 |
| 前伸 | 0.42 | 0.24 | 0.34 |
| 下放 | 0.44 | 0.24 | 0.36 |

数值单位是状态机使用的 `joint_slew` 标度。橙子松爪单独使用
`CHENGZI_PLACE_RELEASE_JOINT_SLEW=2.00`。

## 6. 双臂夹持商品的时延和强制收尾门槛

| 常量 | 当前值 | 作用 |
| --- | ---: | --- |
| `TISSUE_STAGE_SETTLE_SEC` | 0.12 s | 双臂中间路点到位后的同步防抖 |
| `TISSUE_CLAMP_SETTLE_SEC` | 1.20 s | 双臂夹紧后保持侧向夹持力再抬升 |
| `TISSUE_PLACE_LOWER_SETTLE_SEC` | 0.20 s | 落桌反馈到位后保持 |
| `TISSUE_RELEASE_SETTLE_SEC` | 0.10 s | 双臂外移达到释放间距后的保持 |
| `TISSUE_PLACE_LOWER_FORCE_RELEASE_SEC` | 4.0 s | 接触反馈不收敛时仍进入必做释放链 |
| `TISSUE_RELEASE_FORCE_LIFT_SEC` | 3.0 s | 释放间距反馈不收敛时仍进入抬升 |
| `TISSUE_RELEASE_LIFT_FORCE_RETREAT_SEC` | 3.0 s | 抬升反馈不收敛时仍开始退出桌边 |
| `TISSUE_MOTION_TIMEOUT_SEC` | 45.0 s | 双臂负载动作的通用故障上限 |

放置时两只夹爪保持闭合，依靠左右整条手臂向外分离解除侧向夹持，然后执行抬起和
直接后退。4/3/3秒三个值是反馈异常时保证收尾链继续执行的上限，正常反馈到位会更早
切换，并不会每次固定等待这些时间。

负载导航相关值：

- 线速度上限 `TISSUE_NAV_SPEED_LIMIT_MPS=0.045 m/s`；
- Nav2 最大角速度 `TISSUE_NAV_MAX_ANGULAR_RADPS=0.35 rad/s`；
- 离柜预转速度 `TISSUE_PRETURN_MAX_ANGULAR_RADPS=0.35 rad/s`；
- 预转总超时60 s，预转后等停车最多5 s；
- 来源柜预转：A右90°、B右180°、C左150°、D左90°、E左70°；
- 放置完成后恢复常规 MPPI 最大角速度 `NORMAL_MPPI_MAX_ANGULAR_RADPS=1.8 rad/s`。

## 15. 总计时起止点

计时开始条件：里程计首次确认底盘发生真实移动，线速度超过0.005 m/s或角速度超过
0.010 rad/s。收到任务、等待 Nav2 激活和首次规划不计入移动总时长。

计时结束条件：最后一件商品已经完成放置链，随后完成抬起、直接退出桌边并停车。
恢复初始姿态和继续导航不在结束条件之后执行。结果覆盖写入项目根目录的
`mission_total_time.txt`。

## 16. 调参原则

- 到位后停顿明显：检查对应 `SETTLE/DWELL` 和反馈条件；
- 卡住很久才报错：检查 `TIMEOUT`，不要把超时误当正常动作时延；
- 动作过程慢：调整线/角速度、加速度或 `joint_slew`；
- 全局路径刷新慢：修改两个行为树 XML 的 `RateController`；
- 局部避障反应慢：检查 Controller Server 10 Hz 和 local costmap 8 Hz；
- 商品提前松开：先检查高度、夹爪、关节和静止反馈，不要只缩短等待；
- 双臂负载易掉落：检查夹持间距、夹紧保持、负载限速和离柜预转，而不是增加普通
